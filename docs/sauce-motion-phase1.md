# Sauce Motion Engine — Phase 1

Status: implemented and typechecked. Phase 2 capture/compositing/audio and Phase 3 editor UI remain outside this commit.

## Existing integration and backwards compatibility

Current production stack: Playwright capture → sauce.session.v1 trace → Python/OpenCV/FFmpeg renderer. The TypeScript planner is compiled to CommonJS and called by the existing Python bridge over stdin/stdout. The separate Remotion studio is not the production 60fps renderer.

No preset in the input: the previous sauce-studio-motion-v1 bridge contract and silent export semantics remain unchanged.

Explicit preset: the bridge adds a versioned motionEngine property. It contains a full validated SaucePreset; framePlan (sauce-frame-plan-v1) with source/output clocks, spring camera, hero moments and cut candidates; and foleyPlan (sauce-foley-plan-v1) with 48kHz sample positions, cue IDs, gains, mute state and duck intervals.

## Phase 1 modules

- src/types.ts — pure JSON contracts for SaucePreset, FramePlan, FoleyPlan and existing StudioMotion.
- src/presets.ts — validated one-click Clean Studio, 3D Launch, Hyper-Cut with safe deep overrides.
- src/timeWarp.ts — configurable 600ms idle detection, 400/300 action windows, cubic speed ramps.
- src/cameraRig.ts — exact analytic damped springs, 180/24/1 default, 1200px perspective, event-first zoom and bounded tilt.
- src/autoDirector.ts — high-intent hero ranking, click deduplication, callouts and cut-candidate metadata.
- src/foleyPlan.ts — output-clock-aligned click/modal/camera cue schedule, 48kHz sample offsets and music duck instructions.
- src/bridge.ts — preset opt-in without breaking the existing Python v1 consumer.
- src/tests/engine.test.ts — preset validation, camera and timing, Foley, JSON determinism and legacy regression tests.

Hyper-Cut emits editDecisions with kind=cut-candidate but does not yet apply actual hard jumps to rendered video. Time mapping remains smooth and monotonic until Phase 2 applies a validated cut policy.

## Real verified Brimble trace

Source duration: 4200ms. Clean Studio: 4200ms/252 frames; 3D Launch: 3267.85186ms/197 frames; Hyper-Cut: 3004.92326ms/181 frames, all at planned 60fps.

The actual trace enriched with existing safe selector metadata produces a Connect Agent callout for 3D Launch. Repeated planning runs return identical JSON hashes. No audio was generated or muxed in Phase 1.

## Phase 2 handoff — mandatory

1. ACTIVE ELEMENT RIM GLOW: cinematic_stage.py must draw a subtle 1px luminous rim and local elevated shadow around the evidence-backed active target when camera.spotlightActive is true and camera.spotlightBox is valid. Projection must use the same homography as cursor/callout anchors, with surrounding inactive regions blurred up to 6px while the target stays sharp.
2. PROCEDURAL FOLEY FALLBACK: foley_mixer.py must support local licensed WAV/OGG assets and deterministic NumPy/SciPy synthesis for click_crisp, whoosh_soft and pop_glass. Use outputSample positions, 48kHz mixing, volume/mute/ducking and peak limiting, then mux via FFmpeg. No external sample dependency.
3. Capture changes: emit redacted copy, paste and submit events with real timestamps and verified target bounds. Never record clipboard content or secret input values.
4. Python entrypoint: accept --preset 3d-launch and validate the versioned motionEngine payload. FramePlan and FoleyPlan must come from the same planner invocation.
5. Phase 3: actual 1080p60 MP4 + 48kHz audio verification, UI preset picker and responsive editor tests.

Production footage and Foley are NOT yet generated by the new preset contract. Phase 1 is planning only.
