# Sauce v19 — WebGL optics, 3D parallax, code-aware focus, and audio-reactive light

**Live landscape film:** https://devmcp.davemafy.xyz/sauce-engine-v19/

**Source baseline for comparison:** https://devmcp.davemafy.xyz/sauce-engine-v18/

This release builds four **data-driven, optional** finishing capabilities
into the actual Chromium/OpenCV/FFmpeg production path. It does not
reconstruct application UI, invent user actions, or claim that an optical
filter automatically makes a film better. The default product film now
runs WebGL2 finishing and restrained cursor-driven 3D parallax.

## 1 — Real WebGL2 shader finishing

`assets/shaders/optics-webgl2.html` contains a compiled GLSL ES 3.0
fragment shader that samples the final complete film frame as a texture.
It applies:
- chromatic edge separation peaking at **0.00085 UV units**, confined
  to the extreme frame edges by a smooth radial mask;
- deterministic **2% monochrome grain** with a frame-index seed;
- a **maximum 8% radial vignette**.

`scripts/webgl_optics.py` creates a genuine
`canvas.getContext("webgl2")` in Chromium, uploads pixels to a
`TEXTURE_2D`, executes `drawArrays`, and reads back the finished
render. `scripts/postprocess_webgl_video.py` decodes each video frame,
runs the shader, and encodes a full H.264 master. If WebGL2 is
unavailable or reports a GLSL error, this mode **fails explicitly**
rather than pretending a CPU filter is WebGL.

The current Vultr VM has no dedicated GPU. Chromium uses **SwiftShader
software WebGL2**, which is deterministic and functional but noticeably
slower than dedicated hardware. No GPU-speed claims are made.

The shader orientation was checked against the source video: an
initial upside-down image issue was fixed before the final export.

## 2 — Velocity-driven 3D window parallax

`scripts/spatial_parallax.py` differentiates the fixed-60fps
`Spring2D` cursor path, normalizes the velocity, and damps the
result through another critically damped spring. Tilt is clamped to
**±2.5°** along X and Y.

`scripts/cinematic_stage.py` uses real
`cv2.getPerspectiveTransform` and `warpPerspective` to project the
window and occlusion shadow in 3D. `CinematicCursor` uses the exact
same homography on its click hotspot and ripple, so clicking never
visually separates from the UI it targets.

The v19 Brimble film reaches approximately **1.0126°** maximum
absolute tilt. No randomly generated camera or pointer motion is added.

## 3 — Evidence-backed AST and terminal focus

`scripts/session_capture.py` recognizes elements marked
`data-sauce-code-file` or `data-code-file` and their known
`data-line-number`/`data-sauce-line` metadata. Only those
interactions emit `code-focus` events, with time, file, active line,
visible DOM box and line metrics. Actual terminal elements emit a
separate `terminal-focus` event with bounds, **not a fake AST**.

`scripts/code_semantics.py` parses Python with the standard
`ast` module, and JS/TS/JSX/TSX with the pinned `@babel/parser`
package in `scripts/package.json` and `package-lock.json`.
Source paths are confined to an explicit `--code-root` workspace.
The smallest enclosing function/method/class is identified; a zoom
target is derived from its declaration, active line and recorded
editor geometry, at the event's actual timestamp.

During that code cue, `semantic_camera_track` uses a spring to
focus the active block while preserving the real browser UI and its
existing syntax colors. `highlight_code_region` applies a restrained
local emphasis. Ordinary clicks generate no code focus.

This is **not** an AI guessing code semantics from a screenshot. For
editor integrations, the file path and active line must be supplied in
the trace. Files may change after capture; production integrations
should pin their source revision for historical replay.

## 4 — Audio RMS and transient-driven background light

`scripts/audio_reactive.py` decodes a provided audio file with FFmpeg
to **48 kHz mono float PCM**, computes 60fps-windowed RMS and
positive rising transients, normalizes by the robust 95th percentile
and applies different attack/release smoothing.

`CinematicStage.render(...,glow=amplitude)` uses these values to
light only the **area outside the product window**, leaving code and
UI text untouched. Production `--audio-track path` also muxes
the supplied audio into both master and preview. Silent sessions
remain silent; **no music is autogenerated by default**.

## Reproduction

```bash
../.sauce-render-env/bin/python scripts/produce_cinematic_demo.py \
  --session studio/.tmp/brimble-reference-v16-ink \
  --workflow tests/fixtures/brimble-cinematic-workflow.json \
  --out studio/.tmp/nextgen-output \
  --seconds 4.2 --title "Connect your agent" \
  --cursor-scale 0.56 \
  --presentation-hide-selector 'img[src*="bee-cutout"]'
```

Default: WebGL2 optics **on**, inertial parallax **on**. The one-click
producer now runs the WebGL finishing stage between verified real-DOM
replay and preview generation, retaining audio when supplied. Debug
flags `--no-webgl-optics` and `--no-parallax` explicitly disable
the effects.

To enable the two data-dependent effects, use
`--audio-track /path/to/licensed.wav` and
`--code-root /path/to/your/source/tree` with a matching trace.

**v19 actual film:** 252 WebGL-processed frames, 1920×1080, 60fps;
all 3 semantic action checks and 3 visual-region comparisons passed
on the original replay. Master and Lanczos-preview were decoded to
completion. Browser input was captured at 2× DPR; cursor scale remains
0.56 (~32×39 pixels).

**What the v19 sample does not show:** The Brimble session has no
`code-focus` event and no supplied audio. AST camera focus and
audio-reactive glow were therefore verified separately with controlled
Python/TypeScript editor and WAV transient fixtures rather than being
fabricated into the public sample.

The current proof is 4.2 seconds. It is not a long-form, audio-directed
launch film or objective evidence that Sauce surpasses agency output.
