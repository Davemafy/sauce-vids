## Why we rebuilt it

The first Sauce / Linear auto-zoom film contained two unrelated interactions. It
proved a camera movement, not product storytelling. This film follows one
complete task in real software: select five expense amounts, choose currency
format, and display the changed values. Its narration, native input, camera
and captions follow that action instead of treating the cursor as an
arbitrary zoom trigger.

No recreated product UI. No invented app output. No staged screenshot swapped
in after a mouse click.

## What was actually recorded

Source application: **OpenSheets 2.1.0**, licensed MIT:
https://github.com/w0h1v/OpenSheets

Exact application checkout used: `8a26f8a` (local clone under
`sauce-film-lab/OpenSheets` on Vultr). The **public** OpenSheets demo was
used for initial feasibility tests, but the final capture uses our **local
OpenSheets Vite instance** at `http://127.0.0.1:5177`, without other live
demo users or a customer account.

The example sheet contains fictional expense rows, populated **inside the
real editor** using Playwright clipboard paste before recording. Column
widths and header type are adjusted through the application's native UI.
Those setup actions are not presented as part of the filmed tutorial.

The filmed interaction uses a continuous Chromium desktop X11 capture with
`ffmpeg -f x11grab` at **1600 × 900, 60fps, 720 source frames, 12.0 seconds**.
During capture, the visible pointer, press, release and drag are generated by
native X11/XTest events on the same display, not synthetic SVG pointer artwork
or separate fake Playwright cursor graphics. Original source video and
timestamped DOM-event sidecar are left outside the repository under
`studio/.tmp/film-paradigm` on Vultr.

Events from the original capture:
- Native five-cell selection verified at approximately 3.7448s.
- Real Currency toolbar clicked at approximately 4.9487s.
- Native app state change verified at approximately 4.9755s.
- 186 actual cursor-position samples.
- All five actual gridcell accessibility labels changed:
  `320 → $320.00`, `75 → $75.00`, `150 → $150.00`,
  `24 → $24.00`, `45 → $45.00`.

Only the two application actions necessary for the task appear in the filmed
sequence. The actual product UI remains the filmed input.

## Direction and finishing

1. `scripts/film_voice.py` synthesizes the concise five-phrase
   narration **offline** using the local Kokoro v1.0 INT8 model, voice
   `af_heart`, without ElevenLabs or paid API calls.
2. `scripts/align_voice.py` uses local Faster Whisper `base.en` on the
   already-generated voice recording to measure per-word timings. It cross-
   checks the known narration tokens before composing captions.
3. `scripts/record_opensheets_story.py` captures the **real** app's
   operation with the visible native pointer and original DOM event log.
4. `scripts/render_editorial_product_film.py` composes original recording,
   two deliberate camera pushes, a long results hold, an overview pullback,
   timed phrase captions with moving per-word emphasis, an operator-provided
   licensed music file, and the actual narration. The camera's target comes
   from the real recorded selected-amount and formatted-result rectangles.
   Its *timings* are editorial decisions based on narration and observed
   source-event times, not an automatic generalized film director.
5. FFmpeg validates video decode and frame counts, normalizes final audio to
   approximately **-16.1 LUFS integrated / -1.5 dBTP true peak**, then
   produces a 720p/30fps lower-bandwidth alternative. Local Whisper
   re-transcribed the **mixed master audio** to the complete intended script.

No Screen Studio media, footage, or proprietary source code was copied.
The earlier reference served as a qualitative comparison of camera grammar,
not a source asset.

## Reproduction in our Vultr environment

Requirements: Ubuntu, FFmpeg/FFprobe, Chromium, Xvfb display `:93`,
Python with Playwright and python-xlib, Python with OpenCV/numpy/Pillow,
Kokoro ONNX and local voices file, Faster Whisper (for alignment).
Use compatible browser binaries and allow sufficient free disk space.

```bash
# OpenSheets app, pinned from its own repository for deterministic capture:
git clone https://github.com/w0h1v/OpenSheets sauce-film-lab/OpenSheets
cd sauce-film-lab/OpenSheets
git checkout 8a26f8a
npm ci
npm run dev -- --host 127.0.0.1 --port 5177
```

On the independent capture session:

```bash
Xvfb :93 -screen 0 1600x900x24 -nolisten tcp -ac &
export SAUCE_CHROME_BIN=/path/to/chrome
export SAUCE_OPENSHEETS_URL=http://127.0.0.1:5177/

python scripts/film_voice.py
python scripts/align_voice.py
python scripts/record_opensheets_story.py
python scripts/render_editorial_product_film.py
```

Use the configured interpreter for each script; requirements differ.
Do not overwrite a user's existing display session. The scripts intentionally
produce ignored local output receipts, not invented remote screenshot URLs.

## Quality limits

This is **one credible, authored 11-second product film** in a
specific accessible open-source web app. It is not proof that Sauce can yet
autonomously direct every SaaS product, capture authenticated workflows, or
produce a commercial launch campaign without intervention. The result has no
recorded human webcam presenter. A premium 30-second film remains an
additional creative and acceptance task.

The meaningful advance over our earlier auto-zoom proof is **a complete
verified task, voice-first shot decisions, phrase-level semantic sync,
word-level caption emphasis, and reproducible audio/visual delivery**.
