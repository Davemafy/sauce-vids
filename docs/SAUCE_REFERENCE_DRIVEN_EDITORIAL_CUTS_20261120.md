## Why and what was actually researched

A failure of the last Gemini autonomous films was not merely weak prompts or a missing glass effect: our camera compositor interpolated every spatial move, producing a monotonous small browser screenshot regardless of the director's intent. The source-true renderer lacked the deliberate *cut* between an action close-up and a product reveal.

This study obtained and **visually inspected actual external reference MP4s**, including frame-contact sheets, rather than treating internal rejected Sauce films as gold.

## Reusable engine improvement, guarded JSON syntax

`scripts/spatial_studio_stage.py` now supports studio camera key `cut:true`: a genuine *native-source-frame* physical-camera switch. It holds previous pose until the exact source frame, then applies the next perspective pose. No browser UI re-render, fake cursor click, synthetic product transition or interpolation at the actual cut. A director should prefer genuinely verified action/result anchors over guessed screen `center`. A model packet now contains source-hash-bound, exact measured `candidateCuts` nativeFrame/atSeconds for each real event, using actual pixel appearance or conservative DOM time.

Constraints: at most 3 cuts; each 0.35s apart; exactly aligned to source FPS; `startAt=at`; no cut at exclusive last frame; result-focused cut cannot predate evidence; real click target and pointer must remain in frame, and final verified result+context must meet declared overview visibility. The existing 45px-per60fps-equivalent smooth motion limit applies **to every interpolated edge**, while only explicitly verified camera-cut boundaries are exempt. The feature is opt-in; no original camera JSON changes by default.

`scripts/studio_plan_bounded_repair.py` optionally (with exact original source + manifest) eliminates no-op `easing=quintic` (the engine's only easing), redundant default `center=[.5,.5]` when explicit verified focus exists, and scales **only the final `overview` camera** down <=0.22 if strictly needed to honor the model's own context-minimum; leaves all source hashes/geometry/timing/earlier shots unchanged. It never remaps nondefault center, invents UI, silently accepts fake audio or weak creative quality, and always requires full unchanged renderer revalidation.

`scripts/auto_direct_studio_film.py` supports up to two opt-in <12MiB **rights-cleared private** UI reference study MP4s, included alongside genuine source in the director call, with SHA256 provenance receipts and explicit prohibitions on copying UI/assets, never promoted as approved executable reference JSON or source state. Without reference options, old source-only workflows run as before.

Tests: targeted tests for action-frame cuts, strict native time, early state prohibition, creative camera motion, default quintic-only no-op, preserved model first pass, bounded overview fit, and model packet frame evidence; *full suite and exact Glass Loupe regression still needed at documentation writing stage*, add verified status in living handoff instead of inventing passing counts. All model films remain **research-only** pending independent human visual sign-off and end-to-end production URL-capture integration; current opt-in CLI is not the deployed job endpoint.

**Underlying bottleneck not yet cracked:** A genuine recorded 1920px dense web page projected as **one planar texture** cannot reproduce the selective independent interface-layer focus and precise typography depth in the external Raycast/Jitter reference films, even with more good camera cuts. Future premium studies should address **source-native high-resolution capture, per-component real DOM layer extraction/visibility masks and independent protected text legibility**. Do not mistake 371 green tests, a reference-conditioned render or a pretty dark stage for $50K film quality.
